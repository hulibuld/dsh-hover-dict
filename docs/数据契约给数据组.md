# 数据契约（给数据组）

这份文件把 T1 数据任务需要的字段口径写死。**权威定义在 `docs/架构.md` §4**，
这里是同一份契约的施工清单，加上「数据组的实际产出与本契约有出入时怎么办」。

一句话总则：**本文件与 `架构.md` §4 冲突时，以实现者能直接跑起来的那一侧为准；
两边都不能直接跑时，改本文件并在群里说一声。**

---

## 1. 三个文件，三个位置

```
dsh-hover-dict/data/dict.dat    词条      → Entry[]
dsh-hover-dict/data/变位索引   查询表    → Record<string, number>
dsh-hover-dict/data/meta.json   元信息    → DictMeta
```

文件名**不许改**。宿主侧 `index.js` 的 `ASSETS` 与客户端 `net.js` 的 `ASSET_PATHS`
都硬编码了这三个名字，改了要两边一起改。

---

## 2. `dict.dat`

一个 JSON **数组**，每项是定长数组 `Entry`。

```json
[
  ["prevent", [["v","防止"],["v","阻碍"]], "to keep from happening", ["cet4","cet6"], 4, 1,
   [["prevents","第三人称单数"],["prevented","过去式"]],
   [["The rain prevented us from going.","下雨使我们没能去成。"]]]
]
```

### 2.1 Entry 的 8 个槽位

| 下标 | 字段 | 类型 | 必填 | 取值范围 | 硬约束 |
|---|---|---|---|---|---|
| 0 | `w` | string | ✅ | 1–64 字符 | 全小写；`/^[a-z][a-z'-]*$/`；不含空格 |
| 1 | `senses` | Sense[] | ✅ | 长度 ≥ 1 | 空数组的词**不要进词库** |
| 2 | `def` | string | ✅ | 0–400 字符 | 没有就 `""`，**不许 null / undefined** |
| 3 | `tags` | string[] | ✅ | 取自 `cet4`/`cet6`/`ky`/`ielts` | 去重；没有就 `[]` |
| 4 | `collins` | number | ✅ | 0–5 整数 | 0 = 无星级；**不许 null** |
| 5 | `oxford` | number | ✅ | 0 或 1 | 用数字不用布尔 |
| 6 | `forms` | Form[] | ✅ | 0–8 项 | 没有就 `[]` |
| 7 | `examples` | Example[] | ✅ | 0–3 项 | **构建期截到 3 条** |

**为什么全都要给、不许省略**：列式布局靠下标定位。少一个槽位后面的全错位，
而且是静默错位（界面上显示成另一个字段的内容）。用一个 `null` 占位比省略安全，
但本次契约要求用类型正确的空值（`""` / `[]` / `0`），便于实现者不用判 null。

### 2.2 Sense

```
Sense = [pos, zh]
```

| 位 | 字段 | 类型 | 取值范围 | 说明 |
|---|---|---|---|---|
| 0 | `pos` | string | 见下表 | **不带点**。ECDICT 里是 `n.`，构建期去掉点 |
| 1 | `zh` | string | 1–200 字符 | 已 trim；不含词性前缀；多义用 `；` 分隔**不要**拆成多条 |

`pos` 的合法值（其余一律当 `n` 处理并记一条警告）：

```
n       名词
v       动词
a       形容词
ad      副词
prep    介词
conj    连词
pron    代词
num     数词
art     冠词
int     感叹词
aux     助动词
abbr    缩写
```

### 2.3 Form

```
Form = [form, label]
```

| 位 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `form` | string | 变位形式，全小写 |
| 1 | `label` | string | 给人看的标签，见下 |

`label` 建议取值（界面直接显示，不要用英文）：

```
第三人称单数 / 过去式 / 过去分词 / 现在分词 / 复数 / 比较级 / 最高级
```

### 2.4 Example

```
Example = [en, zh]
```

| 位 | 字段 | 类型 | 取值范围 |
|---|---|---|---|
| 0 | `en` | string | 5–300 字符 |
| 1 | `zh` | string | 1–300 字符 |

**例句筛选口径**（数据组已实测：Tatoeba 英中句对 78,293 组，筛长度后约 6.9 万组）：
保持数据组现有的筛选即可。唯一的额外要求是 **en 必须真的包含该词或其变位形式**
（大小写不敏感）——不包含的例句放在这个词下面没有意义。

## 3. 变位索引（运行时从词条 forms 现场建，不再单独存文件）

一个扁平 JSON 对象：查询键 → `dict.dat` 数组下标。

```json
{
  "prevent": 0,
  "prevents": 0,
  "prevented": 0,
  "preventing": 0,
  "prevention": 8412,
  "run": 1841,
  "ran": 1841,
  "running": 1841
}
```

| 项 | 类型 | 取值范围 | 硬约束 |
|---|---|---|---|
| 键 | string | 1–64 字符 | 全小写；撇号用 `'`（U+0027），**不许**用 `’`（U+2019） |
| 值 | number | `0 ≤ v < dict.dat.length` | 越界的值客户端会读到 `undefined` 然后崩溃 |

### 三条容易错的地方

**一、冲突键怎么处理。**

同一个键可能指向多个词条。例：`lay` 既是 `lie` 的过去式，也是独立动词；
`found` 既是 `find` 的过去式，也是独立动词 `found`（建立）。

规则：**保留词头那条，丢弃变位那条。** 用户悬停 `lay` 时更可能想查 `lay` 本身。

**二、原形要不要进表。**

要进。4.3 万键是"变位展开后"的，展开过程通常会把原形也放进去。
但为了保险，客户端另有一条兜底（原形直接在词头表里找），所以**漏了也不会查不到**，
只是慢一步。

**三、派生词不是变位。**

`prevent` → `prevention` 是派生，不是变位，**不要**放进 变位索引（运行时从词条 forms 现场建，不再单独存文件） 的
`prevent` 组里。`prevention` 自己是一个词条，有自己的下标。

## 4. `meta.json`

```json
{
  "schema": 1,
  "builtAt": "2026-10-30T08:12:03.000Z",
  "entries": 20800,
  "keys": 43000,
  "examples": 69000,
  "sources": ["ECDICT", "Tatoeba"],
  "licenses": { "ecdict": "MIT", "tatoeba": "CC-BY-2.0-FR" }
}
```

| 字段 | 类型 | 取值范围 | 说明 |
|---|---|---|---|
| `schema` | number | **必须是 `1`** | 客户端只认 1；别的值拒绝加载并提示升级插件 |
| `builtAt` | string | ISO 8601 | 构建时刻 |
| `entries` | number | 1–200000 | 必须等于 `dict.dat.length`；客户端用它做一致性校验 |
| `keys` | number | 1–500000 | 必须等于 `Object.keys(变位索引).length` |
| `examples` | number | 0–500000 | 例句组总数（不是词条里有例句的数量） |
| `sources` | string[] | 1–8 项 | 建议固定为 `["ECDICT","Tatoeba"]` |
| `licenses` | object | 可为 `{}` | 许可证名。**界面要展示，这是合规要求** |

`schema` / `entries` / `keys` 三个字段是**校验用**，不是装饰。
客户端加载时会比对，对不上就拒绝加载并给出明确错误——这比让错位的数据跑起来好。

## 5. 数据组已实测的事实（直接采信，不要重新验证）

| 事实 | 数值 | 对本契约的影响 |
|---|---|---|
| ECDICT 全库 | 76 万词条 | 筛到 2.08 万才打包，**不要全量输出**（会到 30 MB 以上） |
| 筛选口径 | 考纲标签 or `frq ≤ 20000` or 柯林斯星级 or 牛津3000 | 产出 2.08 万条 |
| ECDICT `pos` 字段 | **全空** | 词性只能从 `translation` 每行开头的 `n.` / `v.` / `a.` / `ad.` 前缀解析 |
| 带前缀的行占比 | 87.7% | 剩下 12.3% 没有词性 → 见 §6.1 |
| ECDICT `detail` 字段 | 空（设计占位） | **ECDICT 完全没有例句**，例句全部来自 Tatoeba |
| Tatoeba 英中句对 | 78,293 组，筛长度后约 6.9 万组 | 覆盖约一半核心词 |
| 变位展开后查询键 | 约 4.3 万 | 变位索引（运行时从词条 forms 现场建，不再单独存文件） 的规模 |
| 未压缩体积 | 约 1.6 MB | 目标体积 |
| gzip 后 | 约 0.63 MB | 传输成本 |

**覆盖率约一半是已知且接受的。** 核心 2 万词覆盖日常阅读的绝大多数；
剩下那一半本来也不该查（专有名词、代码标识符）。不要为了凑覆盖率把例句
从别处抓来——那会引入许可问题。

## 6. 边界与兜底

### 6.1 那 12.3% 没有词性前缀的行

三种处理，按优先级：

1. **优先丢**。一个没有词性的义项在界面上显示成什么？`n. 某种含义` 可能是错的。
2. 若这个词因为别的原因必须保留（比如是四六级词），把义项归到 `n`，
   并在构建日志里记一条。**不要**凭猜测分到 `v` 或 `a`。
3. 全部义项都没词性的词条，`senses` 为空 → 按 §2.1 的硬约束，**这个词不该进词库**。

### 6.2 词头形态

`w` 必须全小写、无空格、无句点。ECDICT 里的短语（`give up`）、带句点的缩写
（`e.g.`）**全部排除**——本插件的取词算法只认单个英文单词（含连字符与撇号）。

排除清单：
- 含空格
- 含 `.`（句点）—— 但要保留 `n't` 这类撇号
- 首字符不是 a-z
- 长度 > 64

### 6.3 例句对不上的情况

如果某词条筛完例句是 0 条，`examples` 给 `[]`，不要为了填补去用别的词的例句。

### 6.4 JSON 编码

- UTF-8 无 BOM
- 不要 pretty-print（每行一个 `\n` 的格式会让体积翻倍）
- 不要 `\uXXXX` 转义中文（`JSON.stringify` 默认不转义，保持默认即可）

## 7. 产出后自查清单

交给实现者之前，跑一遍：

```
□ 三个文件都在 data/ 下，文件名逐字正确
□ meta.json 的 schema === 1
□ meta.json 的 entries === (JSON.parse(dict.dat)).length
□ meta.json 的 keys === Object.keys(JSON.parse(变位索引)).length
□ dict.dat 每一项的长度都 === 8
□ 每一项的 senses.length >= 1 且 senses[0].length === 2
□ 每个 pos 都在合法枚举里（不带的）
□ 每个 变位索引 的值都在 [0, entries) 区间内
□ 每个 变位索引 的键都全小写，且不含 U+2019
□ 抽查 20 个常用词：prevent / run / make / however / significant，
  每个都能在 变位索引 里查到，且指向的 entry[0] 是它自己或其原形
□ 体积在 1.5–2.5 MB 区间（明显超出说明筛选口径跑偏了）
```

最后一条特别重要：体积是筛选口径的**最灵敏指标**。如果产出 8 MB，
说明没有按 §5 的口径筛；如果产出 200 KB，说明筛过头了。

## 8. 已知的契约差异（待实现者处理）

截至目前，数据组的产出还没定稿，以下是**已知可能出差异**的点，
实现者遇到时按右侧处理，不要为此去改数据组的产出：

| 可能的差异 | 处理方式 |
|---|---|
| `dict.dat` 是对象数组（带键名）而不是列式数组 | `loadDictionary` 里加一层归一化：对象形状也接受，转成列式。**但要告诉架构师**，因为体积会涨 140 KB |
| `meta.json` 缺 `examples` 或 `licenses` | 缺省填 `0` / `{}`，不要让加载失败 |
| `tags` 里出现契约外的标签（如 `toefl`、`gre`） | **保留不丢**，`config.js` 的 `tagLabel` 对未知标签回原样显示。将来加考纲时不用改数据 |
| 变位索引（运行时从词条 forms 现场建，不再单独存文件） 里有 `’`（弯撇号） | 客户端 `normalizeKey` 会把 `’` 统一成 `'`，所以能查到；但请数据组修正 |
| `collins` 是 `null` 而不是 `0` | `describeEntry` 里 `star: entry[4] || 0`，能兜住 |
| 例句 en 里没有该词 | 不报错，照常显示（只是对用户没帮助）。记一条构建日志 |
| 体积超 3 MB | **停下来找架构师**。这触发了 `架构.md` §3.4 的例外条款，要重新决定二进制格式 |
