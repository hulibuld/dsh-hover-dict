## 二、红线回归：正文 DOM 零改动

设计 §0 红线一。**本版两道保险**：

1. **主路径（CSS Custom Highlight API）**：把 `Range` 交给浏览器，浏览器渲染时上色。
   我们一个正文节点都没碰、一个属性都没加 —— 红线是**结构性满足**，不是靠约束代码行为。
2. **回退路径（overlay 色块）**：老浏览器不支持 Highlight 时启用，仍然只写插件自己的覆盖层节点。

smoke 里的具体断言（全部 PASS）：

```
PASS  正文 DOM 逐节点未变（红线）  —— 指纹一致
PASS  正文节点数未增  —— 2 vs 2
PASS  正文没有新增属性  —— data-chat-flow-kind
PASS  正文段落没有子节点被插入
PASS  正文里不存在任何 hd-mark
PASS  Highlight 路径跑完正文指纹不变（红线）
```

**指纹判定法**：造一棵「正文」树（`<p>` + `[data-variant="think"]` 内的 `<p>`），
渲染着色层前后各拍一次快照 —— 每节点的 `tagName / 属性集 / 子节点数 / textContent`
拼成字符串，断言**逐字节相同**。这比「断言没有 span」强：任何属性改动、任何空白变化都会被抓到。

**方案演进说明（重要，不算偏离设计意图）**

设计 §C2 原本写的是「`position:fixed` 半透明色块 + 下划线」。实现完成后用户实测报
**「上下滑动界面时红色色块不跟字、偏移」**，随即裁定原话：

> 「我们不需要下划线和色块啊，只要改字的颜色即可。」

于是改用浏览器原生 **CSS Custom Highlight API**：

| 维度 | 原方案（色块） | 现方案（Highlight） |
|---|---|---|
| 改正文 DOM | 不改（画在覆盖层） | 不改（浏览器渲染时上色） |
| 滚动跟字 | 需 rAF 逐帧重测（速度上线） | **天然跟随**，零重测 |
| 单帧成本 | 224 块 × getClientRects | 一次建 Range，之后浏览器负责 |
| 视觉 | 底色 + 下划线 | 只有字色 |

**因此删除了整套滚动快路径**（`createScrollTracker` 294 行 + 140 行测试）——
它治的是色块方案的病，换了方案病根不存在。这是**减法**，不是未完成项。

两条路径并存：`supportsHighlight()` 为真走 Highlight（现代浏览器），
否则/注册失败回退色块（老浏览器）。回退路径代码与测试完整保留。

## 五、遗留项与已知限制

按影响排序。**都不阻塞本版交付**，但要在下一版处理。

### 1. `build.mjs` 多行 import 花括号内注释会被当成导入名（构建器缺陷）

`transform()` 处理多行 import 时，把中间每行拼进 statement 后用 `/\{([^}]*)\}/`
按逗号切名字。**如果注释写在 import 的花括号内部**，注释文字会被当作导入名写进产物，
报错是模糊的 `产物语法错误：Unexpected token '{'`，很难定位到「是注释惹的」。
**规避**：import 列表里不要写行内注释。**建议**：取名字前先剥 `//` 与 `/* */`。

### 2. `card.js` 与 `review.js` 的复习背面有重复（可选去重）

`card.js` 的大卡片背面和 `review.js` 的 `ReviewCardBack` 渲染同一类内容
（词头 + 音标 + 义项 + 例句）。视觉已对齐，但代码是两份。
**建议**：让 `card.js` 也复用 `ReviewCardBack`，只保留一处。

### 3. 探针两坑（写测试的人会踩）

- **`options.local` 注入**：`createWordbook` 的 localStorage 兜底是 `options.local`，
  不是 `options.storage`（后者是宿主 KV）。只传 `storage` 时 KV 走 mock、local 走真
  `window.localStorage`，测试会串。
- **`makePrimitives` 要先调**：`ui.js` 的组件是工厂产物，必须 `const P = makePrimitives(h)`
  之后再 `P.Card`，直接 `h(Card)` 拿不到。

### 4. `locale/*.json` 运行时不读（界面文案硬编码中文）

17 个键的 zh/en 齐平，但**代码里没有读它们的路径** —— 界面全是硬编码中文。
`meta.title`/`meta.description` 由宿主市场页读取（那个有效）。
**结论**：i18n 是后续版本的事，本版双语文件只是「先把文案收拢好」，不承诺切换语言生效。

### 5. README 着色章节本轮已修正

原 README 还在描述「红色底加下划线 / 三档样式」，与用户裁定后的「只改字色」不符。
本轮改为描述 Highlight API 方案，并说明「滚动时颜色跟字走，不可能错位」。
**这条已修复**，列在这里是为了让 lead 知道文档曾经失真过。

### 6. `markStyle` 三档已废弃但仍保留导出

`config.js` 的 `MARK_STYLES` 标了 `@deprecated`，渲染层不再使用，设置面板已移除
（t16 删掉 Segment 控件）。保留导出只为**旧存档不炸**（旧 localStorage 里有
`markStyle: 'background'` 时 `clampAppearance` 仍能接受）。
**建议**：下一版彻底删掉该键并在 `clampAppearance` 里忽略它。
