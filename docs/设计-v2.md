## A. 生词本数据层（wordbook.js + srs.js）

### A1. 词条形状 v2

存储单元不变：KV `name:'dsh-hover-dict'`，**version 升到 2**，表仍叫 `words`；localStorage 兜底键不变 `dsh-hover-dict:wordbook`。老记录读入时就地升级（缺字段补默认），写回时带 `v:2`。**不许改 UNIT_NAME/TABLE/FALLBACK_KEY**——改名等于让老用户丢生词。

```js
{
  v: 2,
  head: 'cute',              // 词头，小写，normalizeKey 后
  addedAt: 1698800000000,
  source: 'dsh'|'youdao'|'manual'|'import',
  bookId: 'default',         // 所属词书 id
  note: '',                  // 用户备注，≤500 字符
  gloss: '',                 // 释义快照：导入行自带的释义或有道抓回的释义；词库能查到的词留空（渲染时现查词库）
  state: 'new'|'unknown'|'fuzzy'|'known',   // 三态+未学。词海口径：unknown=完全没见过，fuzzy=见过但记错/混淆
  srs: {
    due: 0,                  // 下次复习时间戳；0=立即可复习
    interval: 0,             // 当前间隔（天）
    ease: 2.5,               // 难度系数，1.3–3.0
    reps: 0,                 // 连续答对次数
    lapses: 0,               // 累计答错次数
    lastReviewAt: 0
  },
  review: { seen: 0, lastSeenAt: 0 }   // 保留 v1 字段：查词次数（E 块用）
}
```

v1 → v2 迁移规则（`adopt()` 里做）：`state` 缺失补 `'new'`；`srs` 缺失补上面默认值；`bookId` 缺失补 `'default'`；`gloss` 缺失补 `''`。v1 的 `review.seen/lastSeenAt` 原样保留。

### A2. 三态语义与手动转换

- `new`：刚收进来，还没复习过。
- `unknown`：复习时标「不认识」（词海的 ✗）。
- `fuzzy`：复习时标「记错」（词海的 ↻）——见过但想错了，和空白是两回事。
- `known`：复习时标「认识」（词海的 ✓）且间隔 ≥ 21 天，或用户在管理台手动转「已掌握」。

管理台每个词可以直接改状态（下拉或三个小按钮），手动转 `known` 时 `srs.due` 设为 30 天后；手动转 `unknown`/`fuzzy` 时 `srs.due=0`（立即回队列）。

### A3. SRS 算法（新文件 srs.js，纯函数，node 可直测）

简化 SM-2，全部以天为单位：

```js
// grade: 'again'(不认识) | 'hard'(记错) | 'good'(认识)
export function nextSrs(srs, grade, now = Date.now()) {
  const DAY = 86400000
  let { interval, ease, reps, lapses } = srs
  if (grade === 'again') {
    reps = 0; lapses += 1; interval = 0
    ease = Math.max(1.3, ease - 0.2)
    return { due: now + 10 * 60000, interval, ease, reps, lapses, lastReviewAt: now }  // 10分钟后重来
  }
  if (grade === 'hard') {
    reps = 0; lapses += 1
    interval = Math.max(1, Math.round(interval * 0.5))
    ease = Math.max(1.3, ease - 0.15)
    return { due: now + interval * DAY, interval, ease, reps, lapses, lastReviewAt: now }
  }
  // good
  reps += 1
  interval = reps === 1 ? 1 : reps === 2 ? 3 : Math.round(interval * ease)
  interval = Math.min(interval, 365)
  ease = Math.min(3.0, ease + 0.02)
  return { due: now + interval * DAY, interval, ease, reps, lapses, lastReviewAt: now }
}

// 评分后的新状态
export function stateAfterGrade(prevState, grade, newInterval) {
  if (grade === 'again') return 'unknown'
  if (grade === 'hard') return 'fuzzy'
  return newInterval >= 21 ? 'known' : prevState === 'new' ? 'fuzzy' : prevState
}
```

复习队列排序（`dueQueue()`）：`due <= now` 的词，先按 `state==='unknown'` 优先、再按 `due` 升序、再按 `addedAt` 升序。收藏（starred，即 inBook）的词天然全在队列里——本插件生词本就是收藏本，不另设 starred 字段。

### A4. 多词书

新增 KV 表 `books`（同 unit version 2 一起建；localStorage 兜底存 `dsh-hover-dict:books`）：

```js
{ id: 'default', name: '默认生词本', createdAt: …, builtin: true }
{ id: 'cet4-20261121', name: '四级词表', createdAt: …, builtin: false }
```

- `default` 书内置、不可删、不可改名；划词收藏一律进 `default`。
- 导入时可新建书（名字用户起）或选已有书；同一词头在不同书里是**同一条记录**（head 是主键），`bookId` 记录首次归属；重复导入到另一本书时不新建记录，只把该书 id 追加进 `alsoIn: string[]`（可选字段）。这样保持「多本词书共用一套复习队列」（星词口径），又不用改主键结构。
- 删书 = 把该书独占的词（`bookId===id` 且 `alsoIn` 为空）移回 `default`，不删词；`alsoIn` 里的引用移除。内置书不可删。

### A5. wordbook API 增量

保留全部现有方法签名（`ready/has/get/add/remove/toggle/touch/list/importMany/size/subscribe`），新增：

```js
grade(word, grade)            // 走 srs.js，更新 state+srs，落盘，emit
setState(word, state)         // 手动转态，规则见 A2
setNote(word, note)
listBooks() / createBook(name) / renameBook(id,name) / removeBook(id)
dueQueue(now?)                // A3 排序
stats()                       // B4 统计用的聚合，见下
importMany(list, source, opts)// opts={bookId,glosses:Map<head,string>}，兼容旧调用（opts 可省）
exportAll()                   // 返回完整 v2 记录数组（导出 JSON 用）
```

`stats()` 返回：`{ total, byState:{new,unknown,fuzzy,known}, dueToday, addedToday, reviewedToday, streak, days:[{date,added,reviewed}×30] }`。`reviewedToday`/`days` 需要新增一个轻量 KV 表 `log`（或 localStorage 键 `dsh-hover-dict:log`，上限 500 条环形）：每次 grade 追加 `{at,head,grade}`。streak=连续有复习记录的天数（今天没复习但昨天有，streak 保持到昨天为止的计数）。

### A6. 单测（client/test/_wordbook.mjs 扩展 + 新增 _srs.mjs）

必测：v1 记录迁移补默认值；nextSrs 三种 grade 的 interval/ease/due 边界（ease 夹 1.3–3.0、interval 封顶 365）；stateAfterGrade 的 known 阈值 21 天；dueQueue 排序（unknown 优先、due 升序）；importMany 带 bookId/glosses；removeBook 词回 default；stats 的 streak 跨天。

### B1. 生词本管理台（tab 1）

替换现在的 chips 墙。布局从上到下：

1. **统计条**：四个 stat 块——总词数 / 今日到期 / 已掌握 / 连续学习天数（数据来自 `stats()`）。
2. **工具行**：搜索框（按词头或释义过滤，输入即筛）＋ 状态筛选芯片（全部/未学/不认识/记错/已掌握，单选）＋ 词书下拉（全部书 + 每本书）＋ 排序下拉（最近添加/最久未复习/字母序）。
3. **词表**：表格化列表，每行——词头（点击展开行内详情：词库释义/音标标签/例句，复用 describeEntry；词库查不到且有 gloss 就显示 gloss；两者都没有显示「词库未收录，暂无释义」，**不假装给释义**，CETgo 口径）｜状态徽章（四色：new 灰/unknown 红/fuzzy 橙/known 绿，全走 state token）｜下次复习（今天/明天/N天后/已到期，相对时间）｜来源徽章（划词/有道/导入/手动）｜操作（改状态下拉、备注编辑、「移出」）。分页：每页 50 行，底部上一页/下一页 + 「第 x/y 页」。**不再截断 120 个**。
4. **批量操作**：行首复选框 + 全选本页；批量「转为已掌握」「移入词书…」「移出」（移出需内联二次确认，沿用 clearPending 模式，不用原生弹窗）。
5. 底部：导出按钮组（txt 一行一词 / CSV 带状态与释义 / JSON 完整备份）＋ 清空（保留现有二次确认）。JSON 备份可在导入页恢复（见 B2）。

### B2. 粘贴导入预览（tab 3，新文件 importer.js）

替换现在「textarea + 一个导入按钮」。流程分两步：

**第一步 输入**：大 textarea（占位文案给三种示例：一行一词 / `word,音标,释义` CSV / 有道导出整段）＋「从文件读取」（`<input type=file accept=".txt,.csv,.tsv,.json">`，FileReader 读文本进同一管道）＋ 目标词书选择（默认书生词本 / 新建书输入框）＋「解析预览」按钮。

**第二步 预览表**（importer.js 纯函数 `parseImportDetailed(text)` 返回逐行结果）：

```js
{ words: [{ head, gloss, phonetic, line, status }], skipped: [{ line, raw, reason }], format: 'plain'|'csv'|'tsv'|'json'|'youdao' }
// status: 'new'(将新增) | 'dup'(已在生词本) | 'nodict'(词库查不到，仍收录但提示)
```

解析规则（在现有 parseImportText 基础上升级，旧函数保留并委托新函数）：
- 自动识别格式：首行含 `word,` 或制表符分隔≥2列 → csv/tsv；整体是合法 JSON 数组 → json（元素为字符串或 `{head|word, gloss|translation}` 对象，兼容本插件 exportAll 的备份恢复，恢复时保留 state/srs/bookId）；否则 plain。
- 每行取第一个英文词片段为 head（沿用现有正则 `/^[a-z][a-z'-]{0,63}$/`）；同行剩余部分若含中文，截取为 gloss（≤120 字符）；形如 `/…/` 或 `[...]` 的片段识别为 phonetic（只存进 gloss 前缀，不单独建字段）。
- 跳过空行、`#` 注释、表头行；跳过的行连原因进 `skipped`，预览表下方折叠展示「跳过 N 行（展开看原因）」——**不静默丢行**。
- 预览表每行：词头｜释义快照｜状态徽章（将新增/已存在/词库未收录）｜行号。顶部汇总「识别 X 词：新增 A、已存在 B、未收录 C」。
- 「确认导入」才写库：`importMany(heads, 'import', {bookId, glosses})`；完成后显示结果条并可一键跳到生词本 tab 看新书。

### B3. 复习卡片（tab 2，新文件 review.js）

词海口径的刷词卡，从 `dueQueue()` 出题：

- 顶部：今日到期 N 个 / 本轮已复习 M 个 / 方向切换「英→中｜中→英」。
- 卡片正面：英→中显示词头（大号字）；中→英显示释义（词库 briefOf 或 gloss；两者都没有的词不进中→英队列）。空格/回车/点卡片翻面。
- 背面：词性+中文义项（≤3条）+例句（有则1条）+发音按钮（E块）。
- 三个评分按钮：**1 ✗ 不认识 / 2 ↻ 记错 / 3 ✓ 认识**（键盘 1/2/3 同效；焦点在输入框时不抢键）。点击走 `wordbook.grade()`，卡片切下一个，进度即时更新。
- 队列空：显示「今天没有到期的词」+ 两个选项「提前复习最早到期的 20 个」「去导入新词」。
- 筛选芯片：全部到期 / 只刷不认识 / 只刷记错 / 指定词书。
- 本轮结束页：正确率、三态分布变化、「再来一轮」。
- 复习中 Esc 退出回统计视图；组件卸载清干净键盘监听。

## C. 正文/思考生词着色（marker.js）

用户需求原话：不会的单词在思考过程中是红色（可改颜色也可选择直接不变颜色），一眼看见自己之前不会的词。

### C1. 着色范围与词集

- 范围：助手回复正文 + 思考内容，即现有 `SELECTORS.allowedRoot`（`[data-chat-flow-kind="assistant-step"]`）容器内的可见文本。代码块/行内代码/公式/链接沿用 HIT_BLOCKERS 排除（复用 hit.js 判定，不重写）。
- 词集：生词本里 `state !== 'known'` 的词头 + 各自变位（复用 app.js `collectBookSet` 的展开逻辑，抽成 marker.js 可复用函数；注意现行 dict.dat 变位串在槽 5 起、格式 `p:ran/i:running`，以 dict.js `parseForms` 为准，**不要按架构.md 旧槽 3 契约写**）。`known` 的词默认不着色（已掌握就不该再刺眼），设置里可开「已掌握也淡色显示」。
- 匹配：文本节点逐词扫描（`/[A-Za-z][A-Za-z'’-]{0,63}/g`），normalizeKey 后查 Set；命中才算。大小写不敏感。

### C2. 画法（红线合规）

**绝不改正文 DOM。** 流程：

1. `TreeWalker(doc, SHOW_TEXT)` 遍历 allowedRoot 内文本节点；对每个节点跑词匹配，命中的区间用 `Range.getClientRects()` 量矩形（跨行逐段，沿用 anchor.js 思路）。
2. 矩形画成 `position:fixed` 的色块 div，渲染进 `shell.overlay`（新组件 `MarkerLayer`，挂在现有 OverlayHost children 里，key 'markers'）。色块 `pointer-events:none`、`z-index` 在浮层之下、`mix-blend-mode:multiply`（亮色主题）——**统一改用半透明底色方案**：`background: color-mix(in srgb, <userColor> 18%, transparent)`，加 `border-bottom: 1.5px solid <userColor>`，文字本身颜色不动（改不了正文，垫底+下划线足以醒目）。暗色主题下 multiply 会发黑，所以不用 blend mode，半透明底色两种主题都成立。
3. 视口裁剪：只画与视口相交的矩形（±200px 余量），单帧色块上限 400 个，超出按距视口中心距离取最近的。
4. 重算时机（全部节流/防抖，不许每帧扫全文）：
   - 初次：词库 ready 且 wordbook ready 后 `requestIdleCallback`；
   - 滚动：`scroll` 监听（capture，含程序滚动）节流 120ms 重算；
   - 正文变化：`MutationObserver` 观察 chatRegion（childList+subtree+characterData），回调防抖 250ms——流式输出期间自然合并成低频重算；
   - 生词本变化：subscribe 里触发重算；
   - resize：重算。
5. 性能预算：一次全量扫描（一屏 ~200 文本节点）必须 <16ms；扫描前先判 `state!=='known'` 词集为空则直接清空色块返回。MutationObserver 回调里不做 DOM 写入以外的重活。
6. 思考区折叠态：ReasoningRow 未展开时正文不在 DOM（宿主 `data-expanded` 控制），TreeWalker 天然扫不到，无需特判；展开后 MutationObserver 触发重算。思考区容器特征：`[data-variant="think"]`（ReasoningRow root，已从宿主产物核实）；如需区分思考/正文着色强度，用 `el.closest('[data-variant="think"]')` 判定，思考区色块透明度可略高（默认同色同强度，先不做差异）。

### C3. 与现有交互的关系

- 色块 pointer-events:none，点击穿透到正文，现有单击取词不受影响。
- 点中被着色的词 → 照常弹浮层；浮层里显示「已在生词本 · 不认识」状态行（popover 加一行小字）。
- 浮层/卡片打开时色块不隐藏（垫底层互不干扰）。

### C4. 设置（config.js ux.appearance 扩展 + B5 面板）

```js
appearance.markWords: true,          // 总开关：false=完全不变色（用户要求的「直接不变颜色」）
appearance.markColor: '#e5484d',     // 默认红。存 hex，UI 用 <input type=color> + 六个预设色块（红/橙/黄/绿/蓝/紫）
appearance.markKnown: false,         // 已掌握词是否淡色显示（透明度减半）
appearance.markStyle: 'underline',   // 'underline'(底色+下划线) | 'background'(仅底色) | 'text'(仅下划线)
```

clampAppearance 扩展：markColor 校验 `/^#[0-9a-f]{6}$/i`，非法回落默认红；markStyle 枚举外回落 underline。设置面板给实时预览句（「The quick brown fox jumps over the lazy dog.」其中几个词按当前配置着色）。开关改动立即生效（marker 重算），不需要重启。

### C5. 单测（新增 client/test/_marker.mjs）

## D. 有道词典登录 + 收藏夹抓取

### D1. 方案选型（定死，不再讨论）

**宿主侧代理 + 用户粘贴 Cookie**，不做账号密码登录。理由：有道登录有验证码/滑块/设备指纹，模拟登录脆弱且要存用户密码（不可接受）；Cookie 方案用户操作成本低（浏览器 F12 复制一次），宿主 Node fetch 无 CORS 限制，抓取稳定。

用户流程（面板文案要写成傻瓜步骤，用户是 IT 小白）：
1. 浏览器打开 dict.youdao.com 并登录；
2. 按 F12 → Network（网络）→ 刷新页面 → 点第一个请求 → Request Headers 里复制整段 Cookie；
3. 粘贴进插件「有道同步」页签的输入框 → 点「保存并验证」；
4. 验证通过显示昵称/词数 → 点「一键抓取收藏夹」→ 进度条 → 完成显示「新增 X 词，已存在 Y 词」，词进生词本（source:'youdao'，可选目标词书）。

### D2. 宿主新增路由（index.js，全部挂在现有 API_PREFIX 下）

| 路由 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/youdao/cookie` | POST | `{ cookie: string }` | `{ ok:true, valid:boolean, nickname?:string }` — 存 Cookie 并当场验证 |
| `/youdao/cookie` | DELETE | — | `{ ok:true }` — 清除已存 Cookie |
| `/youdao/status` | GET | — | `{ ok:true, hasCookie:boolean, valid:boolean, nickname?:string, lastSyncAt:number, lastCount:number }` |
| `/youdao/sync` | POST | `{ bookId?:string }` | `{ ok:true, added:number, dup:number, total:number, words:string[] }` |

实现要点：
- **Cookie 存储**：宿主内存 + 落盘到 `dataDir/youdao-cookie.json`（`{cookie,savedAt,nickname}`，权限 0o600）。**不进 Config、不进 localStorage、不回显给前端完整值**（status 只报 hasCookie）。dataDir 默认包内 data/，该文件加进 .gitignore 与 .npmignore（发包不带用户凭据）。
- **验证与抓取端点**（实现时按此顺序试，哪个通用哪个，全部失败给明确错误）：
  1. `https://dict.youdao.com/wordbook/webapi/v2/word/list?limit=100&offset=N`（新版网页生词本 API，带 Cookie fetch，JSON 里取词头字段）；
  2. 旧版 `https://dict.youdao.com/wordbook/wordlist?p=N&itemPerPage=15`（HTML，正则提取 `<td class="word">…` 或等价结构）；
  3. 验证身份用 `https://dict.youdao.com/login/acc/query/accountinfo` 或生词本首页是否 302 到登录页。
  - **实现者注意**：以上端点是设计期已知形态，有道可能改版。施工时先用 curl 带一份真实 Cookie 探测（测试可用环境变量 `YOUDAO_COOKIE`，没有就跳过联网测试并把探测结果写进任务产出）；若全部失效，实现降级路径：面板提供「手动导出引导」（教用户在有道生词本页全选复制，粘贴进 B2 导入器，format:'youdao'），并把 sync 按钮置灰显示「有道接口改版，请用手动导入」。**不许静默失败**。
- 抓取限速：每页间隔 ≥400ms，单页 limit≤100，总页数上限 200（2万词封顶）；fetch 超时 15s；401/302 到登录页 → 返回 `{ok:false,error:{code:'E_YOUDAO_AUTH',message:'Cookie 已失效，请重新复制'}}`。
- 抓回的词带释义（有道返回里有 trans/definition 字段就取，进 gloss）；`importMany(words,'youdao',{bookId,glosses})`。
- 这些路由是写操作/外网操作，沿用现有 handler 的方法闸门模式扩展；错误形状沿用 `{ok:false,error:{code,message}}`。
- 宿主测试（scripts/test-host.mjs 扩展）：cookie 存取删、status 不含明文 cookie、sync 在无 cookie 时返回 E_YOUDAO_AUTH、fetch 用注入的 mock（createHandler options 加 `youdaoFetch` 可注入，默认 global fetch）——**联网真测不进自动化测试**，避免 CI 依赖外部服务。

### D3. 客户端「有道同步」页签（settings.js）

- 状态卡：未配置（显示四步图文引导，每步一句话+可折叠的详细截图说明文字）/ 已配置有效（昵称+上次同步时间+词数）/ Cookie 失效（红条提示重新复制）。
- Cookie 输入框（password 型，粘贴后不明文回显）＋「保存并验证」「清除」按钮。
- 「一键抓取收藏夹」主按钮 + 目标词书下拉 + 进度条（sync 是一次性 POST，进度用「正在抓取…」动画 + 完成后的数字；不做 SSE）。
- 完成后结果条：新增 X / 已存在 Y，附「去生词本查看」跳转。
- 降级引导区（D2 第3点触发时显示）：三步手动导出说明 + 「打开导入页」按钮。
